> 给刚 fork 这个仓库的开发者用：一次性了解所有模块、请求流、配置项、改东西时该去哪个文件。
> 阅读顺序建议：**1 → 2 → 3 → 6**，遇到具体改动再回查 **4、5、7**。

## 1. 这是什么

一个 Telegram bot，把 [Claude Code](https://claude.ai/code)（通过 `claude-agent-sdk` Python 库）接到 Telegram。用户在 Telegram 发消息，bot 调用 Claude 去操作服务器上的代码目录，再把结果（包含工具调用流、最终答复、图片）回发到 Telegram。

核心能力：
- **Agentic 聊天**（默认）—— 自然语言对话，自动管理 session、自动续接上次会话
- **Classic 命令模式**（开关 `AGENTIC_MODE=false`）—— 13 个 `/xxx` 命令 + inline 键盘
- **多项目 Topic**（开关 `ENABLE_PROJECT_THREADS=true`）—— Telegram 论坛话题 = 一个项目
- **Webhook 触发** —— GitHub/通用 webhook 进来 → 自动触发 Claude → 发消息通知
- **定时任务** —— APScheduler 跑 cron，自动让 Claude 处理预设 prompt
- **MCP 工具** —— 内置一个 MCP server，让 Claude 可以主动给用户发图片
- **语音识别** —— Mistral Voxtral / OpenAI Whisper / 本地 whisper.cpp 三种 provider
- **多层安全** —— 鉴权 / 目录沙箱 / 输入校验 / 速率限制 / 审计日志

技术栈：Python 3.11+ · Poetry · `python-telegram-bot[rate-limiter]` · `claude-agent-sdk` · `aiosqlite` · `fastapi+uvicorn` · `apscheduler` · `pydantic-settings` · `structlog`

## 2. 整体架构

### 启动流程（`src/main.py`）

```
run() → asyncio.run(main())
  ├─ 解析 CLI（--debug, --config-file）
  ├─ setup_logging() 配 structlog
  ├─ load_config() 读 .env + 环境覆盖
  └─ create_application(config) ← 这里串起所有子系统
       │
       ├─ Storage(SQLite)            ← src/storage/facade.py
       ├─ AuthenticationManager     ← Whitelist + Token Provider
       ├─ SecurityValidator / RateLimiter / AuditLogger
       ├─ SQLiteSessionStorage + SessionManager
       ├─ ClaudeSDKManager + ClaudeIntegration  ← Claude 入口（facade）
       ├─ EventBus + EventSecurityMiddleware
       ├─ AgentHandler  ← 订阅 WebhookEvent / ScheduledEvent
       └─ ClaudeCodeBot  ← 注册 PTB Application
            │
            └─ context.bot_data = {auth_manager, claude_integration,
                                   storage, security_validator, ...}
  └─ run_application(app)
       ├─ 信号处理 SIGINT/SIGTERM
       ├─ bot.initialize() + 可选 ProjectThreadManager.sync_topics
       └─ asyncio.gather(
              bot.start(),                # 长轮询或 webhook
              run_api_server(),           # 如果 ENABLE_API_SERVER
              JobScheduler.start(),       # 如果 ENABLE_SCHEDULER
              NotificationService.start() # 总是启动
          )
```

### Agentic 模式请求流

```
Telegram 消息
  └─→ Security 中间件 (group -3) 校验内容
  └─→ Auth 中间件 (group -2) 检查 AuthenticationManager
  └─→ RateLimit 中间件 (group -1) 令牌桶 + 成本预估
  └─→ MessageOrchestrator.agentic_text() (group 10)
       └─→ ClaudeIntegration.run_command()
            ├─ SessionManager.get_or_create_session(user, dir)
            ├─ ClaudeSDKManager.execute_command()   ← 真正调 SDK
            │    └─ ClaudeSDKClient + ClaudeAgentOptions（流式）
            ├─ stream_callback → 把工具调用/思考片段实时发回 Telegram
            ├─ ResultMessage 拿到真实 session_id
            └─ Storage.save_claude_interaction()
       └─→ ResponseFormatter 切分长消息 → 发回 Telegram
```

### 外部触发流（Webhook / 定时任务）

```
POST /webhooks/{provider}                  cron 触发
  ├─ HMAC-SHA256 签名校验                   └─ JobScheduler 发布
  ├─ Bearer token 校验                          ScheduledEvent
  ├─ webhook_events 表原子去重
  └─ 发布 WebhookEvent          ↘     ↙
                              EventBus
                                 ↓
                    EventSecurityMiddleware（鉴权/校验）
                                 ↓
                          AgentHandler.handle_*
                                 ↓
                    ClaudeIntegration.run_command()
                                 ↓
                      发布 AgentResponseEvent
                                 ↓
                       NotificationService
                                 ↓
              Telegram（每 chat ~1.1s 限速）
```

### 中间件分组

PTB 的 `group` 数字越小越先执行：
- `-3` Security
- `-2` Auth
- `-1` Rate limit
- `10` Orchestrator handlers（业务逻辑）

### 依赖注入

所有 handler 通过 `context.bot_data` 拿依赖：
```python
context.bot_data["auth_manager"]
context.bot_data["claude_integration"]
context.bot_data["storage"]
context.bot_data["security_validator"]
context.bot_data["feature_registry"]
# ...
```

## 4. `src/` 各模块详解

### `src/main.py` —— 唯一入口
- `run()` 是 `pyproject.toml` 注册的 `claude-telegram-bot` 命令
- `create_application(config)` 是真正的"装配车间"：所有组件在这里 new 出来并互相串接
- 改启动顺序、加新组件、加新依赖项注入，都在这里改

### `src/exceptions.py` —— 异常树根
```
ClaudeCodeTelegramError
├── ConfigurationError → MissingConfigError, InvalidConfigError
├── SecurityError      → AuthenticationError, AuthorizationError, DirectoryTraversalError
├── ClaudeError        → ClaudeTimeoutError, ClaudeProcessError, ClaudeParsingError
├── StorageError       → DatabaseConnectionError, DataIntegrityError
└── TelegramError      → MessageTooLongError, RateLimitError(=RateLimitExceeded)
```
Claude 模块在 `src/claude/exceptions.py` 又扩了 `ClaudeSessionError`、`ClaudeMCPError`。

### `src/config/` —— 配置
| 文件 | 作用 |
|---|---|
| `settings.py` | `Settings(BaseSettings)` —— 所有环境变量字段定义 + 校验 |
| `loader.py` | `load_config(config_file)` —— 读 `.env` 和环境变量 |
| `features.py` | `FeatureFlags(settings)` —— 只读属性视图：`mcp_enabled`、`git_enabled` 等 |

**改配置项**：在 `settings.py` 加字段 → 在 `features.py` 加一个 property → 在 `.env.example` 写注释。

### `src/bot/` —— Telegram 层

#### `bot/core.py`
- `ClaudeCodeBot` —— 构建 PTB `Application`、注册中间件、注册命令菜单、跑 polling/webhook

#### `bot/orchestrator.py`（**这是 agentic 模式的核心**）
- `MessageOrchestrator` —— 根据 `AGENTIC_MODE` 注册不同 handler
- agentic 方法：`agentic_text`、`agentic_document`、`agentic_photo`、`agentic_voice`、`agentic_repo`
- `_make_stream_callback()` —— 拦截 Claude 流式工具调用，识别 `send_image_to_user` 并收集成 `ImageAttachment`
- Stop 按钮拦截 `stop:*` callback

#### `bot/update_processor.py`
- `StopAwareUpdateProcessor` —— 让停止按钮能打断正在跑的 handler（其他更新仍然串行）

#### `bot/handlers/` —— Classic 模式
| 文件 | 内容 |
|---|---|
| `command.py` | 13 个 `/xxx` 命令：`/start /help /new /continue /end /ls /cd /pwd /projects /status /export /actions /git /restart /sync_threads` |
| `callback.py` | `handle_callback_query` 分发 inline 键盘点击 |
| `message.py` | `handle_text_message / handle_document / handle_photo / handle_voice` |

#### `bot/middleware/`
| 文件 | 作用 |
|---|---|
| `security.py` | 内容危险模式扫描 |
| `auth.py` | `AuthenticationManager.authenticate(user_id)` |
| `rate_limit.py` | 令牌桶 + 成本估算 |

#### `bot/features/` —— 可选功能
`registry.py` 的 `FeatureRegistry` 根据 feature flag 实例化：
- `file_handler.py` —— 文档上传、zip/tar 解压、代码分析（`ProcessedFile`）
- `image_handler.py` —— Telegram 图片 → base64 给 Claude vision
- `voice_handler.py` —— 三种 provider 抽象（Mistral / OpenAI / 本地 whisper.cpp）
- `git_integration.py` —— 安全 git 子命令
- `quick_actions.py` —— `QuickActionManager` + `QuickAction`（classic 专用）
- `session_export.py` —— Markdown / JSON / HTML 导出
- `conversation_mode.py` —— 自动生成后续追问（classic 专用）

#### `bot/utils/`
| 文件 | 作用 |
|---|---|
| `formatting.py` | `ResponseFormatter` —— 切长消息、HTML 安全 |
| `html_format.py` | `escape_html()`、`markdown_to_telegram_html()` —— 偏好 HTML 不用 Markdown v1 |
| `draft_streamer.py` | `DraftStreamer` —— 流式拼接编辑同一条 Telegram 消息 |
| `image_extractor.py` | `ImageAttachment`、路径校验（防越权读图片） |

### `src/claude/` —— Claude Agent SDK 集成

**只用 Python SDK，没有 CLI subprocess 路径。** `docs/SDK_DUPLICATION_REVIEW.md` 审计了哪些本地代码和 SDK 重复、可以删。

| 文件 | 作用 |
|---|---|
| `facade.py` | **`ClaudeIntegration`** —— 所有调用方的入口；`run_command()` 找/建 session、跑 SDK、续接失败时重试、持久化结果、返回 `ClaudeResponse` |
| `sdk_integration.py` | `ClaudeSDKManager`（真正调 `ClaudeSDKClient`）、`ClaudeResponse` 数据类、`StreamUpdate`、权限回调 `_make_can_use_tool_callback` |
| `session.py` | `ClaudeSession` 数据类、抽象 `SessionStorage`、`SessionManager`（内存缓存 + 过期清理 + 每用户上限） |
| `monitor.py` | `check_bash_directory_boundary()` —— 解析 Claude 想跑的 bash 命令，拒绝越出 `APPROVED_DIRECTORY` |
| `exceptions.py` | Claude 专属异常 |

**Session 机制**：session_id 由 Claude 的 `ResultMessage` 返回，**不本地生成**。`SessionManager.get_or_create_session()` 先查缓存 → 查 DB → 新建（`is_new_session=True`，id 为空）→ Claude 执行后 `update_session()` 写真实 id 落库。

### `src/storage/` —— SQLite 持久化（async）

| 文件 | 作用 |
|---|---|
| `database.py` | `DatabaseManager` —— `aiosqlite` 连接池、schema migration、datetime adapter |
| `models.py` | `UserModel / SessionModel / MessageModel / ToolUsageModel / AuditLogModel / CostTrackingModel / ProjectThreadModel` |
| `repositories.py` | 每个模型一个 Repository（CRUD + 业务查询）+ `AnalyticsRepository` |
| `facade.py` | **`Storage`** —— 单一入口：`storage.users`、`storage.sessions`、…；提供 `initialize / close / health_check / save_claude_interaction` |
| `session_storage.py` | `SQLiteSessionStorage` 实现 `claude.session.SessionStorage` 协议 |

> **DateTime 约定**：全部用 `datetime.now(UTC)`（**不**用已弃用的 `datetime.utcnow()`）。SQLite 的 TIMESTAMP/DATETIME 列通过 `detect_types=PARSE_DECLTYPES` 自动转 `datetime`；`from_row()` 里调 `fromisoformat()` 前必须 `isinstance(val, str)` 守卫。

### `src/security/` —— 安全 5 层

| 文件 | 作用 |
|---|---|
| `auth.py` | `AuthProvider` 抽象，`WhitelistAuthProvider`、`TokenAuthProvider`（含 `InMemoryTokenStorage`），`AuthenticationManager` 串联多 provider |
| `validators.py` | `SecurityValidator` —— 路径穿越、危险 shell pattern、文件名校验；可用 `DISABLE_SECURITY_PATTERNS=true` 关掉 |
| `rate_limiter.py` | 令牌桶 `RateLimitBucket` + `RateLimiter`（请求速率 + 成本上限） |
| `audit.py` | `AuditLogger` —— `log_command / log_authentication / log_security_violation`；目前用 `InMemoryAuditStorage`（DB 化是 TODO） |

`ToolMonitor` 在 SDK 流过来的工具调用上做白名单/黑名单校验，可用 `DISABLE_TOOL_VALIDATION=true` 关。

### `src/events/` —— 事件总线

| 文件 | 作用 |
|---|---|
| `bus.py` | `Event` 基类、`EventBus`（typed subscribe/publish、并发派发） |
| `types.py` | `UserMessageEvent / WebhookEvent / ScheduledEvent / AgentResponseEvent` |
| `handlers.py` | `AgentHandler` —— 订阅 webhook+定时事件，调 Claude，发 `AgentResponseEvent` |
| `middleware.py` | `EventSecurityMiddleware` —— 包一层 bus，对 event 做安全过滤 |

纯 stdlib 实现（asyncio + dataclasses），没用第三方 pub/sub。

### `src/api/` —— FastAPI Webhook server

| 文件 | 作用 |
|---|---|
| `server.py` | `create_api_app()` 构建 FastAPI app（`/health`、`/webhooks/{provider}`）；`run_api_server()` 起 uvicorn |
| `auth.py` | `verify_github_signature()`（HMAC-SHA256），`verify_shared_secret()`（Bearer token） |

**默认端口** `API_SERVER_PORT=8080`，由 `ENABLE_API_SERVER` 开关控制。

### `src/scheduler/` —— 定时任务

| 文件 | 作用 |
|---|---|
| `scheduler.py` | `JobScheduler` —— 包一层 APScheduler 的 `AsyncIOScheduler`；任务持久化到同一个 SQLite |

提供 `add_job(name, cron_expr, prompt, working_directory, ...)` 编程接口。任务跑起来后通过 EventBus 发 `ScheduledEvent` → `AgentHandler` 接力。

### `src/notifications/` —— 通知服务

| 文件 | 作用 |
|---|---|
| `service.py` | `NotificationService` —— 订阅 `AgentResponseEvent`；每个 chat ~1.1s 限速队列；`_last_send_per_chat` 字典 |

环境变量 `NOTIFICATION_CHAT_IDS` 设默认收件人。

### `src/projects/` —— 多项目话题

| 文件 | 作用 |
|---|---|
| `registry.py` | `ProjectDefinition / ProjectRegistry`，`load_project_registry(yaml_path, approved_dir)` |
| `thread_manager.py` | `ProjectThreadManager.sync_topics()`、`resolve_project(chat_id, thread_id)` |

`ENABLE_PROJECT_THREADS=true` 开启。`PROJECT_THREADS_MODE=group` 时一个 Telegram 论坛群里每个项目一个 topic，`private` 时每个用户私聊里用 topic 区分。同步限速 `PROJECT_THREADS_SYNC_ACTION_INTERVAL_SECONDS`（默认 1.1）。

配置示例：`config/projects.example.yaml`。

### `src/mcp/` —— 内置 MCP server

| 文件 | 作用 |
|---|---|
| `telegram_server.py` | 用官方 `mcp` 包的 `FastMCP` 起一个 stdio MCP server，目前只暴露一个工具 `send_image_to_user(file_path, caption)` |

发图实际由 bot 端的 `_make_stream_callback` 拦截工具调用，收集成 `ImageAttachment` 在 run 结束后发出（MCP server 进程本身**不发图**）。配 Claude 用这个 MCP server 见 `config/mcp.example.json`。

### `src/utils/`

| 文件 | 作用 |
|---|---|
| `constants.py` | `TELEGRAM_MAX_MESSAGE_LENGTH=4096`、`SAFE_MESSAGE_LENGTH=4000`、`MAX_FILE_SIZE_MB=10`、`ALLOWED_FILE_EXTENSIONS`、`DANGEROUS_PATTERNS`、`DEFAULT_DATABASE_URL`、Claude 超时/turn 上限、重试退避 |

这里**只有常量没有工具函数**，工具函数都散在各自模块里。

## 5. 配置项参考

完整字段在 `src/config/settings.py`；下面是分组速记。

### 必填
- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_BOT_USERNAME`
- `APPROVED_DIRECTORY` —— 沙箱根目录，所有 Claude 的文件 / bash 操作都被限制在内

### 鉴权
- `ALLOWED_USERS` —— 逗号分隔 Telegram user id 白名单
- `ENABLE_TOKEN_AUTH` + `AUTH_TOKEN_SECRET` —— 启用 token 鉴权

### Claude
- `ANTHROPIC_API_KEY` —— 给 SDK 用
- `CLAUDE_TIMEOUT_SECONDS`、`CLAUDE_MAX_TURNS`、`CLAUDE_MAX_COST_PER_USER`
- `ENABLE_MCP` + `MCP_CONFIG_PATH`

### Agentic 平台
- `AGENTIC_MODE` (默认 `true`)
- `ENABLE_API_SERVER`、`API_SERVER_PORT` (默认 8080)
- `GITHUB_WEBHOOK_SECRET`、`WEBHOOK_API_SECRET`
- `ENABLE_SCHEDULER`
- `NOTIFICATION_CHAT_IDS`

### 安全放宽（仅可信环境）
- `DISABLE_SECURITY_PATTERNS=true` —— 关 SecurityValidator 的 shell pattern 检查
- `DISABLE_TOOL_VALIDATION=true` —— 关 ToolMonitor 的工具名校验

### 多项目话题
- `ENABLE_PROJECT_THREADS`
- `PROJECT_THREADS_MODE` (`private` | `group`)
- `PROJECT_THREADS_CHAT_ID`（group 模式必填）
- `PROJECTS_CONFIG_PATH`
- `PROJECT_THREADS_SYNC_ACTION_INTERVAL_SECONDS`（默认 1.1，0 = 关限速）

### 输出详细度
- `VERBOSE_LEVEL` 0/1/2（用户也能用 `/verbose 0|1|2` 临时改）
  - 0 安静（只发最终答复）
  - 1 普通（显示工具名 + 思考片段）
  - 2 详细（工具名 + 输入摘要 + 较长思考）

### 语音
- `ENABLE_VOICE_MESSAGES` (默认 true)
- `VOICE_PROVIDER` (`mistral` | `openai` | `local`，默认 `mistral`)
- `MISTRAL_API_KEY` / `OPENAI_API_KEY`
- `VOICE_TRANSCRIPTION_MODEL`
- 本地模式：`WHISPER_CPP_BINARY_PATH`、`WHISPER_CPP_MODEL_PATH`（需自己装 ffmpeg + whisper.cpp）

## 6. 开发任务速查

### 常用 Make 目标

```bash
make dev          # poetry install + pre-commit install
make run          # 跑 bot
make run-watch    # 文件改动自动重启（watchfiles）
make run-debug    # 带 --debug 跑
make test         # pytest + coverage
make lint         # black --check + isort --check + flake8 + mypy
make format       # 自动 black + isort
make clean        # 清缓存

# 跑单个测试
poetry run pytest tests/unit/test_claude/test_facade.py -k test_name -v

# 只跑类型检查
poetry run mypy src

# 发版
make bump-patch   # 或 bump-minor / bump-major
make release      # 推 tag 触发 GitHub release.yml
```

远程 Mac 部署（tmux 持久化）：`make run-remote / remote-attach / remote-stop`。

### 代码风格

- **Black** 88 字符行宽
- **isort** black profile
- **flake8** 扩展忽略 `E203,W503`
- **mypy** strict（`disallow_untyped_defs=true`，所有函数必须有类型注解）
- **autoflake** 删未用 import
- 日志全用 `structlog`（prod JSON / dev 控制台）
- 数据时间一律 `datetime.now(UTC)`

### "我想改 X，去哪个文件"

| 想做的 | 改这里 |
|---|---|
| 加一个新的 `/xxx` 命令 | agentic：`src/bot/orchestrator.py` 的 `_register_agentic_handlers` + `get_bot_commands`；classic：`src/bot/handlers/command.py` + `_register_classic_handlers` |
| 改 Claude 的调用方式 | `src/claude/facade.py` + `src/claude/sdk_integration.py` |
| 收紧/放宽路径/命令校验 | `src/security/validators.py` + `src/claude/monitor.py` |
| 加一种新鉴权方式 | 实现 `AuthProvider`（`src/security/auth.py`），在 `main.py:create_application` 串进 `AuthenticationManager` |
| 加一种新事件 | `src/events/types.py` 定义，`src/events/handlers.py` 订阅 |
| 加一个新的 webhook 源 | `src/api/server.py` 加路由 + `src/api/auth.py` 加校验 |
| 编程方式加定时任务 | `src/scheduler/scheduler.py` 的 `JobScheduler.add_job()` |
| 加一个 feature flag | `src/config/settings.py` 加字段 + `src/config/features.py` 加 property + `.env.example` 加注释 |
| 改 DB schema | `src/storage/database.py`（migration）+ `src/storage/models.py`（dataclass）+ `src/storage/repositories.py`（CRUD） |
| 改 Telegram 消息渲染 | `src/bot/utils/formatting.py`（切分）或 `src/bot/utils/html_format.py`（HTML 转义） |
| 加一个 MCP 工具给 Claude 用 | `src/mcp/telegram_server.py` 加 `@mcp.tool()`，然后在 `src/bot/orchestrator.py:_make_stream_callback` 加拦截逻辑 |
| 改速率限制默认值 | 默认值在 `src/utils/constants.py`，逻辑在 `src/security/rate_limiter.py` |
| 加项目到 thread 模式 | 改你自己的 `projects.yaml`（参考 `config/projects.example.yaml`），路由在 `src/projects/thread_manager.py` |
| 改启动顺序 / 加新组件 | `src/main.py:create_application` |

## 8. 部署 / 运维提示

- **systemd 部署** 见仓库根 `SYSTEMD_SETUP.md`
- **远程 Mac mini** 部署用 `make run-remote`（解锁 keychain + tmux session `claude-bot`）
- **SQLite 数据库** 默认 `data/bot.db`，由 `DEFAULT_DATABASE_URL` 控制
- **日志** 用 `structlog`：dev 是彩色控制台，prod 是 JSON（便于喂给 Loki / ELK）
- **CI**：`.github/workflows/ci.yml` 跑 lint + 测试；`release.yml` 在打 tag 后构建发布
